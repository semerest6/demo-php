# Common Definition of Done

A task is done when, as applicable:
- requested behavior works end-to-end;
- project remains runnable/buildable;
- relevant checks pass;
- important visual/manual results were inspected when needed;
- errors and limitations are explicit;
- no secrets or unintended sensitive data were added;
- unrelated work was not overwritten;
- documentation/current state and meaningful project context were updated;
- the user has a concise verification path when useful.

If an external dependency, access limitation or missing user decision blocks the rest, clearly identify the verified portion and blocker.
