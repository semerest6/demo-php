# Documentation Policy

Update relevant documentation when truth materially changes: behavior, architecture, contracts/API, data model, security, deployment/startup, development workflow, user-visible operation or current project status.

Avoid duplication:
- common reusable AI workflow belongs in ai-workflow-core;
- project-specific rules belong in `.ai/PROJECT_RULES.md`;
- current truth belongs in project state/canonical docs;
- chronology belongs in task/session history.

Code/runtime evidence wins over stale documentation for current-state questions.
